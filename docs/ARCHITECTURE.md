# Architecture

## Data flow

| Stage | Runs on | What it does | Code |
|---|---|---|---|
| PipeGen pipeline | GPU, in PipeGen's DeepStream container | decode → `nvinfer` (TensorRT engine) → tracker → `meta_json` / VMS / MQTT | generated by PipeGen; driven by `scripts/pipegen_ctl.sh` |
| Adapter | CPU | detects the layout, timestamp unit and coordinates; outputs `DetFrame`s | `crowdshield/io_pipegen.py` |
| Geometry | CPU | homography, foot point, resolution rescale, area filter | `crowdshield/geometry.py` |
| Tracking | CPU | PipeGen's tracker IDs; NN fallback only when IDs are missing | `crowdshield/tracker.py` |
| Kinematics | CPU | per-track velocity (≥ 1 s baseline, EMA) | `crowdshield/kinematics.py` |
| Fields | CPU, numpy | density, velocity, speed and pressure on a 1 m grid at 5 Hz | `crowdshield/fields.py` |
| Assessor | CPU | status with hysteresis, turbulence, forecast, risk, events | `crowdshield/assess.py` |
| Publisher | CPU | v1 messages to MQTT and a JSONL mirror; incident log; actuator command | `crowdshield/publish.py` |
| Gateway | CPU | MQTT ingest and validation, history, incidents, health, calibration, frames, allow-listed control, HTTP + WebSocket | `gateway/` |
| UI | browser | Command (WebGL2 field), Steward, Calibrate, Judge, System | `ui/` |

## Why PipeGen is load-bearing

- **Every pixel is processed by PipeGen's pipeline.** Detection, the TensorRT engine and tracking all run in the DeepStream app that PipeGen generates. CrowdShield contains no detector, pose model or other network; `tests/test_static.py` fails if one is imported.
- **The tracker IDs are PipeGen's.** Velocity, and therefore crowd pressure (the main warning), needs stable IDs. The engine uses them as they arrive, and labels the source `pipeline.tracker = "pipegen"`.
- **The exported run is used, not reproduced.** `scripts/pipegen_ctl.sh` runs PipeGen's own `run.sh`/`run.vms.sh` inside PipeGen's container to switch sources and to run headless. PipeGen's project files are never edited.
- **Speed, precision and model name come from PipeGen.** The FP16 and INT8 comparison uses PipeGen's speed reports; CrowdShield never measures or guesses them.

## Process layout on the demo laptop

```
Windows browser ──http://localhost:8080──► WSL: gateway (python -m gateway)
                                              ▲ MQTT 1883 (system mosquitto)
WSL: engine (python -m crowdshield.run --source tail:~/.crowdshield/run/metadata.json)
                                              ▲ file, one JSON frame per line
Docker (PipeGen container): gst-launch-1.0 ... nvinfer_backport ... MetaJson   (GPU)
```

## Contract

`docs/DATA_CONTRACT.md` (v 1) defines the topics, payloads, units and status rules. `crowdshield/schema.py` validates messages in the engine tests and at the gateway's ingest, where invalid messages are counted and never crash anything.

## Honesty mechanisms

- `pipeline.source` is one of `live`, `video`, `replay`, `synthetic` or `sim`. Every screen shows a label for anything that isn't live, and the time river fades stretches that weren't live.
- The stale overlay appears after 3 s without data, the status greys to "last known", and the sign shows NO DATA.
- `docs/RESULTS.md` is generated, and every section names its input file. Judge mode shows only numbers taken from files or the live feed.
